# REVIEW.md

Defects I found in the starter `app/main.py`. The numbers in the "notice it" column are things I actually ran against the original helpers.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds the shift start by `replace()`-ing the hour/minute on the punch-in's own (UTC, naive) datetime. The shift is in IST, so the comparison is against the wrong clock. | Punch-in at 09:40:01 IST gives `0` (should be 10); 10:15:59 IST gives `0` (should be 45). Nobody is ever late. | New `shift_window()` builds the IST shift start for the attendance date; `calc_late_minutes` works on aware datetimes. |
| 2 | `compute_late_minutes` | Grace rule is wrong: it floors to whole minutes first and then tests `> 10`, so 10:01 after start (floor = 10) is not late. R2 says strictly more than 10:00. Overnight shifts (start on the previous day) are not handled either. | 09:40:01 on a 09:30 shift returns 0. A 22:00 shift with punch-in at 02:00 uses the wrong day. | Compare the exact seconds `> 600`, then floor to minutes. Shift start comes from the attendance date, so overnight works. |
| 3 | `compute_work_hours` | Uses Python `round()` on a float, which is banker's rounding, not half-up (R4). Also no truncation of microseconds. | 450 seconds is exactly 0.125 h and returns `0.12`; R4 wants `0.13`. | Decimal arithmetic with `ROUND_HALF_UP` (`half_up()`), seconds truncated first. |
| 4 | `compute_overtime` | No 30-minute minimum (R3). It uses shift_end on the same date, so overnight shifts are wrong. It subtracts an IST-aware datetime from a naive `punch_out`. | 10 minutes after shift end returns `10` instead of `0`. With a naive datetime from PyMongo it raises `TypeError: can't subtract offset-naive and offset-aware datetimes`, which is a 500. | `calc_overtime` uses the shift end from `shift_window()` (next day for overnight), floors minutes, returns 0 below 30. All datetimes are aware. |
| 5 | module level `MongoClient(...)` | No `tz_aware=True`, so every datetime read back is naive and easy to mix with local time. | Mixing aware and naive values raises or silently shifts by 5h30. | `tz_aware=True`; conversions to/from epoch ms are in `ms_to_dt` / `dt_to_ms`. |
| 6 | no indexes at all | Nothing enforces uniqueness and every query is a collection scan. | Two concurrent creates or punch-ins can both succeed. `/attendance` slows down with 100k rows. | `ensure_indexes()` at startup (idempotent); the unique indexes are what the race guards rely on. |
| 7 | `/health` | Always returns ok, even when Mongo is down. | Stop Mongo: `/health` is still 200. | Pings Mongo, returns 503 if it fails. A global handler also maps `PyMongoError` to 503 instead of a 500. |
| 8 | `EmployeeIn` | No validation: `emp_code` format, email, `HH:MM`, `joined_on` as a real date, lengths, and `shift_start != shift_end` are all unchecked. | `joined_on: "yesterday"` or `emp_code: "x"` is accepted and stored. | Field patterns/lengths plus validators; all return 422. |
| 9 | `create_employee` | Check-then-insert race (`find_one` then `insert_one`). `created_at` is `datetime.now()` (naive, server-local) and is returned as an ISO string instead of epoch ms. | Fire two identical POSTs in parallel: both get 201 and there are two employees. | Unique index on `emp_code`, catch `DuplicateKeyError` for 409. `created_at` is UTC and returned in epoch ms. |
| 10 | `list_employees` | `skip = page * page_size` skips the first page. `total` counts the whole collection, ignoring the filter. No sort, so pages are not stable. `page_size=0` becomes `limit(0)`, which in Mongo means no limit. Negative page gives a negative skip, which errors. | `page=1` never returns the first rows. `department=Sales` returns a `total` of everything. | `skip = (page-1)*page_size`, filtered `total`, `sort emp_code`, `page >= 1` and `1 <= page_size <= 100` validated. |
| 11 | `punch_in` | If the employee does not exist, `emp["shift_start"]` is `None[...]`. | Unknown `emp_code` returns 500 instead of 404. | `get_employee()` raises 404. |
| 12 | `punch_in` / `PunchInIn` | `status` is any string, so `ABSENT` or garbage can be stored. `if body.punched_at` treats `0` as "not provided". Seconds, floats and strings are not rejected. `datetime.fromtimestamp(ms/1000)` uses the server's local zone, and the float division loses precision. | `status: "BANANA"` returns 201. `punched_at: 1783312500` (seconds) is accepted and lands in 1970. | `Literal` status, strict int with the epoch-ms range, conversion through exact `timedelta(milliseconds=...)`. |
| 13 | `punch_in` | `date` is taken from the server-local date instead of the IST date (R1), no overnight rule, and no truncation to whole seconds. | A punch at 00:30 IST gets the previous day's date when the server runs in UTC. A 22:00 shift punch-in at 02:00 gets the wrong day. | `attendance_date()` applies R1, `replace(microsecond=0)` truncates. |
| 14 | `punch_in` | Check-then-insert race, same as #9. | Two simultaneous punch-ins both return 201. | Plain `insert_one` guarded by the unique `(emp_code, date)` index; `DuplicateKeyError` becomes 409. |
| 15 | `punch_in` response | Returns `id` (the ObjectId as a string), which the contract says never appears. `punch_in` is returned as a datetime, not epoch ms. | Response has an `id` key and an ISO date string. | `record_out()` builds the response from scratch (no `_id`, epoch ms). |
| 16 | `list_attendance` | Loads the whole collection with `find(q)`, sorts in Python, slices. Sort has no `emp_code` tie-break. No validation of dates, `date_from > date_to`, status or page size. Page 0 slices with a negative index. Legacy documents without `history` / `half_day` are returned as they are. | At 100k rows it is slow and memory-heavy. `page=0` returns the wrong rows. | Query built in `attendance_filter`, sorted/skipped/limited by Mongo with the `(date desc, emp_code)` index, `count_documents` for the filtered total, validation added, `record_out()` fills defaults. |
| 17 | whole file | No handling of Mongo errors (any outage is a 500). | Kill Mongo mid-request. | Global `PyMongoError` handler returning 503. |

## Looked at and decided it was fine
* `load_dotenv()` with the default `override=False`: values already in the environment win over `.env`, which is what the contract asks for. I left it.
* The localhost / `attendance_db` fallbacks for `MONGO_URI` / `MONGO_DB`: harmless for local development because the environment overrides them.
* `status_code=201` on the two create endpoints and the `{"_id": 0}` projection in `list_employees`: correct.
* `create_employee` popping `_id` from the dict after `insert_one` (insert adds it): worked, but I now build the response explicitly in `employee_out()`.

I did not reuse the three helper functions as they were; the fixes above amount to a rewrite, so they are replaced by `calc_late_minutes`, `calc_work_hours`, `calc_overtime` and `derive()`.
